## 一、这个固件是什么

```
文件名：fairy-stackchan-universal.bin
大小：  ~11.9 MB（整机合并固件，含 bootloader + 分区表 + 应用）
芯片：  ESP32-S3（M5Stack StackChan / CoreS3）

★ "universal（通用）" 的含义：
   不含任何服务器 IP ⇒ 谁刷都行，不会连到别人的服务器上

   ⚠️ 但请注意：这也意味着【它第一次开机会连官方服务器】。
      怎么让它转到你自己的服务器，见第三节（★ 必读）。
```

### 和作者自己用的固件有什么区别

| | 通用版（Release 下载） | 作者自用版 |
|---|---|---|
| 服务器地址 | ❌ 不含（自己填） | ✅ 写死作者的内网 IP |
| 双皮肤 | ✅ 有 | ✅ 有 |
| 摸头/甩晕/爱心 | ✅ 有 | ✅ 有 |
| 唤醒词 | ✅ Hi Fairy + 你好小智 | ✅ 同 |
| 设置服务器地址 | ✅ **支持**（配网页填 / 语音说，见第三节） | ✅ 同 |

**⇒ 功能完全一样，只差"服务器地址"这一项。**

## 二、怎么刷

### 烧录方法 A：用 M5Stack 官方工具（推荐新手）

```
1. 打开 https://docs.m5stack.com/en/download  （或用 Chrome 内核浏览器）
   ⇒ 搜 "M5Burner"，或者在网页版烧录工具里选 StackChan

2. 用 USB-C 线把设备连电脑（★ 要数据线，不是充电线）

3. 在烧录工具里选「自定义固件」→ 选择本目录的
   fairy-stackchan-universal.bin

4. 点烧录，等待完成（约 1~2 分钟）
```

### 烧录方法 B：用 esptool（命令行）

```bash
# 装工具
pip install esptool

# 烧录（★ 端口按实际改，Windows 是 COM3 这样的名字）
esptool.py --chip esp32s3 --port /dev/ttyACM0 --baud 921600 \
  write_flash 0x0 fairy-stackchan-universal.bin
```

> ⚠️ 这是**合并固件**，所以烧到 `0x0` 就行（不用分别烧 bootloader/分区表/app）。

### 烧录方法 C：设备已有小智固件 ⇒ 用 OTA 升级（最省事）

```
如果设备里已经有小智固件（能连上服务器）：
  1. 把你的服务器做成 OTA 服务（本项目服务器自带，见 INSTALL.md）
  2. 把本固件放到 OTA 目录，让设备自己升级
  ⇒ 细节看 xiaozhi-esp32 上游文档
```

## 三、★★ 刷完之后：怎么让它连【你自己的服务器】

**这是最关键的一步，也是本项目最容易被误解的一步 —— 先把它说清楚。**

### ⚠️ 先讲实话：「不用编译」≠「什么都不用做」

```text
设备「第一次」连哪台服务器，只有两个来源（见 ota.cc）：

    ① 设备 NVS 里存的 ota_url     —— 全新设备是【空的】
    ② 编译期写进固件的 CONFIG_OTA_URL —— 通用固件是【官方默认地址】

⇒ 所以：全新设备 + 通用固件 = 第一次开机【必然先连官方服务器】
   （api.tenclass.net，上游默认值）
```

**能写 NVS 的入口有四个 —— 只有第 1 个不需要设备先连上任何服务器：**

| # | 写入方式 | 前提 |
|---|---|---|
| 1 | ★ **设备配网页的「自定义 OTA 地址」** | **无**（手机连设备热点即可） |
| 2 | 语音说「我的服务器是 …」 | 已连上某台服务器（否则收不到这句话） |
| 3 | 网页控制台切皮肤 | 已连上你的服务器（否则打不开控制台） |
| 4 | 切皮肤时自动记住 | 已连上你的服务器 |

⇒ **结论：想「刷完就直连你自己的服务器」，通用固件也能做到** ——
在设备自己的配网页里填一次地址即可（见下面路径 B），不必编译、不必念 IP。

---

### 三条路，按「省事程度」排

| 路径 | 要编译？ | 首次怎么连 | 适合谁 |
|---|---|---|---|
| **A** 编译期写地址 | ✅ 要 | 开机直连，零操作 | 想一劳永逸 / 给朋友用 |
| **B** ★ 通用固件 + 配网页填地址 | ❌ 不要 | 设备热点页里填一次地址 | 不想装工具链（推荐） |
| **C** 通用固件 + 语音说地址 | ❌ 不要 | 先连官方，再用嘴念地址 | 只想临时改一下地址 |

> ⚠️ **关于「在网页里填服务器地址」**：早期文档写成「配网后在 **Web 控制台**填」，
> 那句是错的 —— 控制台是**你自建服务器**上的页面，设备连不上你的服务器就打不开它。
> ★ 但**正确的地方确实存在**：不是控制台，而是**设备自己的配网页**
> （配网模式下手机连设备热点打开的那个页面）⇒ 见下面的路径 B。

---

#### 路径 A（★ 推荐）：编译期烧入地址

> **前提**：你的服务器**已经跑起来了**，并且你知道它的地址。
> 如果还没有，先做 [../INSTALL.md](../INSTALL.md) 第 2 节（服务器部分）
> —— 见该文档 1.0 节的建议工序。

```text
1. 编辑 main/boards/m5stack/core-s3/config.json，在 sdkconfig_append 里加：
       "CONFIG_OTA_URL=\"http://<你的IP>:8003/xiaozhi/ota/\""

2. idf.py build  →  idf.py -p <串口> flash

⇒ 刷完开机就直接连你的服务器，什么都不用做。
```

> ★ **给朋友用推荐这条**：你帮他编译好，地址直接编进去，
> 他拿到就能用，不用念 IP、不用碰配置。
>
> ⚠️ 代价：这个固件**只适合你们自己用**，别公开分发（会泄露内网 IP）。

#### 路径 B（★ 免编译推荐）：通用固件 + 在设备配网页填地址

```text
① 让设备进【配网模式】
     全新设备：第一次开机会自动进
     已配网的设备：开机后（状态还在 Starting 时）点一下屏幕；
                   或 WiFi 连不上时自动进

② 手机连设备的热点（名字见屏幕提示，形如 Xiaozhi-XXXX）
③ 浏览器打开配置页（屏幕上显示的那个地址）
④ 切到 Advanced 页签（中文界面是「高级选项」）→ 填「自定义 OTA 地址」：
      http://<你的服务器IP>:<http_port>/xiaozhi/ota/
   → 保存
⑤ 回「新 Wi-Fi」页签填你家 WiFi 密码 → 设备重启，直连你的服务器
```

> ★ 这个页签里另有「Wi-Fi 最大发射功率 / 记住 BSSID / 启用睡眠模式」三项，
> **不影响连服务器**，一般不用动（各项含义与「睡眠模式」的真实作用见
> [../INSTALL.md](../INSTALL.md) 第 1.5 节）。

> **为什么这条路能成立**：配网页面（`esp-wifi-connect` 组件）自带这个输入框，
> 保存时执行 `nvs_set_str(..., "ota_url", ...)`，写进 **NVS `wifi` 命名空间**
> —— 和固件 `ota.cc` 读的**是同一个键**；这个框在固件里也是**开着的**
> （`main/boards/common/wifi_board.cc` 里 `config.show_ota_config = true`）。
> ⇒ **不需要联网、不需要官方服务器、不用念 IP。**
>
> ★ 这个框默认是**关**的：组件（`78/esp-wifi-connect`）README 写的是
> `Both default to false, hiding the corresponding fields in the config portal`，
> 要显式打开才显示 `Custom OTA URL input`；是 xiaozhi 在 `wifi_board.cc` 里
> 用 `config.show_ota_config = true` 打开的 —— 而 xiaozhi 主文档没对用户讲
> 这个用法，所以大部分人没见过它。

#### 路径 C（备选）：通用固件 + 语音说地址

```text
设备先连上官方服务器（NVS 空时的默认行为），再对它说：
      「我的服务器是 http://<你的服务器IP>:8003/xiaozhi/ota/」
⇒ AI 调设备的本地 MCP 工具 self.server.set_ota_url，
  把地址【直接写进设备 NVS】
⇒ 设备重启，连上你的服务器
```

> ⚠️ **两个现实问题（所以只当备选）：**
>
> ① **必须先有官方服务器可用**（联网 + 官方服务正常）—— 纯离线环境走不通。
> ② **用嘴念 IP 很难念对**。ASR 常把 `<服务器IP>` 听成别的
>    （「一点五」/「幺五」/「一屋」都可能）。

---

### ★ 自动记忆机制（它解决的是「切换不丢」，不是「首次怎么连」）

很多人会把这个机制误解成「零配置自动发现服务器」。**它不是。**

```text
它做的事：
   切到官方【之前】 → 把当前地址存进 fairy_skin/self_ota
   切回 Fairy 时    → 读回来用

⇒ 前提是：你【已经成功连上过一次】你的服务器。
```

**读取优先级**（`skin_manager.cc` `SelfOtaUrl()`）：

```text
① fairy_skin/self_ota   ← 上次切到官方前记下的（最可靠）
② wifi/ota_url          ← 设备当前在用的
③ CONFIG_OTA_URL        ← 编译期兜底
```

**⇒ 效果**：成功连过一次你自己的服务器之后，
在「Fairy ⇄ 官方几何脸」之间反复切换，**地址不会丢**。

> ⚠️ **顺序很重要**：先保证能连上（路径 A / B / C 任一），再折腾切换。
> 否则第 ③ 层兜底若是官方地址，切回 Fairy 时会连到官方去。

---

### ★ 端口是怎么确定的（改过 http_port 的人必读）

设备侧**不再固定按 8003 猜端口**（`skin_manager.cc`）：

```text
① 每次取地址前，用【设备正在用的那条地址】记下「自建地址」
   （端口来自地址本身 ⇒ 确切值）
② 只有该记录为空时，才用服务器下发的 WebSocket 地址推导；
   推导只在「还不知道」时写，绝不覆盖 ① 记下的确切值
③ 推导端口顺序：fairy_skin/http_port（保留键，无写入者）
                → 当前生效地址里的端口 → 8003
```

> ⇒ 推荐（非必须）：改了 `server.http_port` 就用【路径 A 或 B】给**完整地址**
> —— 首次连接就三条路：编译期地址 / 配网页填地址 / 语音说地址，
> 而完整地址自带端口。

> 补充：**服务器侧**（`admin_handler.py`）会读 `server.http_port`，
> 读不到时会打印明确告警：
> `[自适应提示] 配置里没有 server.http_port，OTA 地址推断将兜底使用 8003`

### 怎么确认成功

```text
看设备屏幕 / 听它说话：
  · 成功：界面换成 Fairy 皮肤，说话是人设语气（"我在"、"收到"）
  · 串口日志（若有）：WS: Connecting to ws://<你的服务器IP>:8000/...

如果没成功：
  · 检查服务器地址对不对（浏览器能打开那个 ota/ 链接吗）
  · 检查设备和电脑在同一个 WiFi
  · 检查电脑防火墙有没有拦 8000/8003 端口
```

## 四、双皮肤怎么用

刷完之后设备里有**两套皮肤**，可以随时切：

| 皮肤 | 长相 | 连谁 | 什么时候用 |
|---|---|---|---|
| **Fairy** | 几何脸 + Fairy 人设 | 你自己填的服务器 | 在家 |
| **Geometry** | 官方几何脸 | 官方服务器 | 带出门 |

**切换方式（三种任选）：**

```
① ★ 按设备【电源键】短按 —— 最可靠，断网也能切
② 对设备说：「换成官方表情」「切回 Fairy」
③ 打开 Web 控制台 → 皮肤页 → 点卡片
```

> ⚠️ 切到官方之前，设备会**记住你的自建服务器地址**，
> 下次切回 Fairy 时自动用回来（不用重填）。
